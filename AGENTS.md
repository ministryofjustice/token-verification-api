# AGENTS.md

Guidance for AI coding agents working in this repository.

## Project overview

`token-verification-api` is an HMPPS Spring Boot JSON API (Kotlin) that controls verification of
OAuth2 access and refresh tokens issued to prisoners/staff for HMPPS services. Token records
(`jwtId`, `authJwtId`, `subject`) are stored in Redis with secondary indexes, and expire via
"phantom" records (see README.md for the full Redis data model).

## Tech stack

- Kotlin on Spring Boot, built with Gradle Kotlin DSL (`build.gradle.kts`, wrapper: `./gradlew`)
- Spring Data Redis for persistence, Spring Security OAuth2 resource server for auth
- springdoc-openapi for API docs (Swagger UI)
- Tests: JUnit 5, Mockito-Kotlin, embedded-redis for integration tests, WebTestClient (webflux-test)

## Repository layout

- `src/main/kotlin/uk/gov/justice/digital/hmpps/tokenverification/`
  - `config/` — Spring configuration (security/resource server, OpenAPI, exception handling)
  - `data/` — Redis repository/entity definitions
  - `health/` — health and info endpoint contributors
  - `resource/` — REST controllers
  - `service/` — business logic
- `src/test/kotlin/...` — unit and integration tests mirroring the main package structure
- `src/main/resources/application*.yml` — Spring config per profile (default, dev, local-redis)
- `helm_deploy/` — Helm chart for Cloud Platform (Kubernetes) deployment
- `.github/workflows/` — CI pipeline, security scans (Snyk, OWASP, Veracode, CodeQL), deploy

## Build, run, and test

```bash
./gradlew build          # compile, run tests, run checks
./gradlew bootRun         # run the application locally (needs a Redis instance; see
                          # application-local-redis.yml / docker-compose.yml)
./gradlew test            # run unit/integration tests
```

Prefer running the smallest relevant Gradle test task for the change being made (e.g.
`./gradlew test --tests "uk.gov.justice.digital.hmpps.tokenverification.resource.TokenResourceTest"`)
before falling back to the full `./gradlew build`.

## Conventions

- Kotlin code style follows the project's `.editorconfig`; do not reformat unrelated code.
- Keep controllers thin — put logic in `service/`, Redis access in `data/`.
- Mirror the main package structure when adding tests under `src/test/kotlin`.
- Favor constructor injection and idiomatic Kotlin (data classes, null-safety) over Java-style code.
- This repo follows standard HMPPS/MoJ Digital Spring Boot template conventions shared across
  other `ministryofjustice` HMPPS repositories — check for similar patterns in sibling services
  when unsure.

## Security and secrets

- Never commit real secrets, tokens, or credentials. Config files under `src/main/resources` and
  `helm_deploy/*/values-*.yaml` reference secrets via environment variables / Kubernetes secrets.
- Dependency vulnerability suppressions live in `token-verification-suppressions.xml` and
  `dps-gradle-spring-boot-suppressions.xml` (the latter is regenerated by the gradle plugin —
  avoid hand-editing it; prefer updating the gradle plugin version instead).
- CI runs Snyk, OWASP dependency-check, and Veracode scans (`.github/workflows/security_*.yml`);
  keep dependency changes minimal and justified.

## Pull requests

- Keep changes focused and update `README.md` when behavior or setup instructions change.
- Ensure `./gradlew build` passes locally before proposing a PR.
